# 拾光卡藏 · Gachabase

可自定义内容的中文拆卡、收藏与知识强化界面。深色金色的卡包、插画卡面和独立知识档案，让任何主题都能成为一套收藏。

## 运行

无需安装依赖。运行 `python3 -m http.server 5173 --bind 127.0.0.1`，浏览器打开 `http://127.0.0.1:5173`。也可使用 `npm start`。ES modules 需要 HTTP 服务，不要直接双击 HTML。主体验的图片、样式和脚本均来自本项目，可在本地服务器下离线使用，无外部字体、遥测或付费 API。

## 拆卡和收藏

- 每包五张，包含待机摆动、拆封、错峰展开、3D 翻卡与稀有度光晕。自动揭晓可暂停，也可手动或全部揭晓。减少动态效果同时尊重系统偏好。
- 开包时一次计入收藏。切换页面停止动画；返回或刷新保留本包和已翻状态，不重复发卡。收起卡包仅结束本次展示。
- 五张卡允许分行展示，完整标题可换行；翻卡两面采用相同的内容自适应网格高度。手机优先单列，保留可点击空间。
- 图鉴支持搜索、稀有度与已收藏筛选。卡片详情展示知识、出处、重复数量及备用数量。
- 卡组总数不限；同 ID 最多 2 张，不能超过实际拥有量。没有联网交易或真实资产。

## 知识强化

每种卡以稳定 ID 保存独立等级，默认 **0**。答对 **+1**，答错 **−1**，最低 **0**、最高 **5**；重复副本共享该等级。强化不会改变稀有度，也没有攻防、战斗、签到、冷却减免或抽卡奖励。

在已收藏卡的详情中答题。本轮作答同步结算一次，双击、旧事件或刷新不会重复升降级。答完点击“下一题”；仅有一道题时点击“再答一轮”可开始新的作答。未收藏的卡不能强化；没有 `questions` 的自定义卡会明确提示“暂无题目，不能强化”，不自动编造题目。

旧版原始存档缺少等级时迁移为 0，收藏、卡组和开包进度保留。若旧卡与内置示例的 ID、标题、正文等现有内容字段一致，会补上本项目原创的示例练习和插画映射；自定义或被修改的卡不会被猜测补题。已结算题目随存档保存。更换卡池清空当前作答轮次，保留仍存在 ID 的收藏、卡组与等级；删除的 ID 不再保留进度。相同 ID 表示同一种卡，新主题需要独立进度时请使用新的 ID。

## 自定义卡池

在工作室编辑或导入 JSON，先完整校验再应用。卡池为 `{ "name": "主题名称", "cards": [...] }`，需要 1–500 张卡。卡池编辑、文件导入和规范化导出统一最多 8,000,000 个 UTF-8 字节；完整备份恢复与导出最多 12,000,000 个 UTF-8 字节。

每张卡必填字符串字段：`id`、`title`、`unit`、`category`、`era`、`text`、`source`，以及 `rarity`（N/R/SR/SSR）。ID 用英文字母、数字、连字符和下划线，不重复。文本只作为纯文本显示。

可选 `art` 为本地图案：`bronze`、`qinhan`、`threekingdoms`、`sages`、`emperor`、`redcliffs`。不填写时使用抽象背景，不给任意自定义主题强配历史插画。插画仅为氛围示意，不作为实物或人物肖像依据。

可选 `questions` 为 0–20 道题。每题有 `question`、2–6 个不同的文本 `options`、从 0 开始的正确答案索引 `answer`，以及可选 `explanation`。例如：

```json
{"question":"孔子是哪一学派的创始人？","options":["法家","道家","儒家"],"answer":2,"explanation":"孔子是儒家学派创始人。"}
```

大小按 UTF-8 字节计算，中文通常不等于一个字节，输入中的空白也计入处理大小。即使紧凑 JSON 未超限，规范化导出超过上限仍会在应用前拒绝。接纳卡池前还会按全部卡片可能达到的收藏、卡组、等级、题目和未揭晓批次预留完整备份空间，避免合法状态导出后无法恢复。资源超限会单独说明，不将其称为数据损坏；原进度不会因失败的应用或恢复被替换。

题干、选项和答案索引都会校验。非法等级在恢复时清洗为 0，未知 ID 的等级会移除，无效的作答轮次会清除；错误 JSON 或不合格卡池不会改变当前进度。

## 存档与备份

主体验沿用 `gachabase.v1` 的 localStorage 键，数据结构版本为 2。完整备份包括卡池、收藏、卡组、强化等级、当前作答结算状态、开包次数、未揭晓批次和动态偏好；恢复替换全部现有进度。卡池导出仅导出内容。

存储读取或写入异常会显示可见提示；仍可继续操作和导出完整备份。在详情中保存失败也会显示提示。处理上限不等于浏览器本地存储配额，配额不足时仍可导出内存中的完整备份。若现有本地存档超过处理上限，原存储保留且禁止自动覆盖，只有明确确认应用合格卡池或恢复合格备份后才恢复写入。更换浏览器、端口或清理站点数据前请先导出备份。

## 内容与抽取规则

示例为七年级上学期中国古代史四单元范围的 24 张原创知识摘要及 24 道原创练习。不是教材逐字内容或真题，不代替完整教材；来源和仍需指定印次核对的细节见 [SOURCES.md](SOURCES.md)。插画提取自用户提供的独立 HTML 文件。

N/R/SR/SSR 每张卡的抽取权重分别为 60/25/12/3，按当前池所有卡权重之和归一化、有放回抽取，不是各稀有度固定百分比。稀有度表现通过边框、标记及光晕区分，不表示历史价值。

`data.js` 管理内容，`core.js` 管理校验、抽卡和强化结算，`app.js` 管理交互与可取消时序，`pack-ui.js` 和 `quiz-ui.js` 分别呈现拆包和问答。

## 检查与归档

`npm run check` 仅做 JavaScript 语法检查。没有自动测试任务或 GitHub Actions。逻辑、存档及事件模拟检查的实际范围见 [VERIFICATION.md](VERIFICATION.md)；没有 ego-lite 时不声称完成真实浏览器或手机验收。

`gemini.html` 作为融合前的独立页面归档保留，主体验不再提供入口，也不维护其旧战斗、签到或奖励逻辑。该历史页面使用独立存档和不同 JSON 格式，规则不等同于当前主体验。其 Tailwind CDN、Google Fonts 依赖和 36 张用户数据的核对边界不变。Git 历史和未改动的归档文件均可用于回退。回退主体验到旧版前请导出完整备份，旧版不会保留新增的强化字段。

卡牌已移除 `symbol` 字段及对应徽章。导入旧卡池或备份时会忽略并丢弃该字段，新的导出不再包含它；ID、稀有度、强化和已有进度不因此改变。
